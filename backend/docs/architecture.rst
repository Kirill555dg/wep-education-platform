======================
Архитектура системы
======================

Общий обзор
===========

Backend построен на принципах **многослойной архитектуры** с чёткым разделением ответственности
между компонентами. Система использует асинхронное программирование для обеспечения высокой
производительности при работе с базой данных и внешними сервисами.

Основные паттерны
==================

Service Layer Pattern
---------------------

Вся бизнес-логика изолирована в сервисах. Сервисы:

* Координируют работу нескольких репозиториев
* Реализуют бизнес-правила и валидацию
* Управляют транзакциями
* Не знают о деталях HTTP-протокола

Пример:

.. code-block:: python

    class AuthService:
        def __init__(self, db: AsyncSession):
            self.db = db
            self.user_repo = UserRepository(db)
            self.login_repo = LoginDataRepository(db)

        async def authenticate(self, credentials):
            # Бизнес-логика аутентификации
            user = await self.user_repo.get_by_email(credentials.email)
            # ... проверка пароля, генерация токена и т.д.

Repository Pattern
------------------

Репозитории предоставляют абстрактный интерфейс для работы с данными:

* Инкапсулируют SQL-запросы и ORM-операции
* Предоставляют единый API для CRUD-операций
* Позволяют легко подменять реализацию (например, для тестирования)

Пример:

.. code-block:: python

    class BaseRepository:
        async def get_by_id(self, id: int):
            # Базовая реализация получения по ID

    class UserRepository(BaseRepository):
        async def get_by_email(self, email: str):
            # Специфичный метод для User

Dependency Injection
--------------------

FastAPI предоставляет встроенную систему DI:

.. code-block:: python

    async def get_db() -> AsyncSession:
        async with AsyncSessionLocal() as session:
            yield session

    @router.post("/login")
    async def login(
        credentials: LoginRequest,
        db: AsyncSession = Depends(get_db)
    ):
        service = AuthService(db)
        return await service.authenticate(credentials)

DTO Pattern
-----------

Pydantic схемы используются как Data Transfer Objects:

* Валидация входящих данных
* Сериализация ответов API
* Документация API (через OpenAPI)
* Type safety

Пример:

.. code-block:: python

    class UserCreate(BaseModel):
        email: EmailStr
        password: str
        first_name: str
        last_name: str
        role: UserRole

    class UserResponse(BaseModel):
        id: int
        email: EmailStr
        first_name: str
        role: UserRole
        created_at: datetime

Слои приложения
===============

API Layer
---------

**Файлы**: ``app/api/v1/*.py``

Ответственность:

* Маршрутизация HTTP-запросов
* Валидация входящих данных (через Pydantic)
* Аутентификация и авторизация
* Формирование HTTP-ответов
* Обработка ошибок (преобразование доменных ошибок в HTTP-статусы)

Service Layer
-------------

**Файлы**: ``app/services/*.py``

Ответственность:

* Бизнес-логика
* Координация работы репозиториев
* Валидация бизнес-правил
* Управление транзакциями

Repository Layer
----------------

**Файлы**: ``app/repositories/*.py``

Ответственность:

* CRUD-операции с базой данных
* Построение SQL-запросов через SQLAlchemy
* Фильтрация, сортировка, пагинация
* Кеширование (опционально)

Data Layer
----------

**Файлы**: ``app/models/*.py``

Ответственность:

* Определение структуры таблиц БД
* Отношения между таблицами (foreign keys, relationships)
* Индексы и ограничения

Schema Layer
------------

**Файлы**: ``app/schemas/*.py``

Ответственность:

* Валидация данных
* Сериализация/десериализация
* Документация API

Безопасность
============

Аутентификация
--------------

Используется JWT (JSON Web Tokens):

* Токены генерируются при успешной аутентификации
* Токены содержат user_id и role
* Токены проверяются middleware при каждом запросе

Авторизация
-----------

Проверка прав доступа на уровне сервисов:

* AccessControlService проверяет, имеет ли пользователь доступ к ресурсу
* Разные роли имеют разные права (преподаватель vs студент)

Хранение паролей
----------------

* Пароли хешируются с помощью Argon2
* Соль генерируется автоматически
* Исходные пароли никогда не сохраняются

Обработка ошибок
================

Система использует иерархию доменных ошибок:

.. code-block:: python

    class DomainError(Exception):
        """Базовый класс для доменных ошибок"""

    class NotFoundError(DomainError):
        """Ресурс не найден"""

    class ForbiddenError(DomainError):
        """Доступ запрещен"""

    class BadRequestError(DomainError):
        """Некорректный запрос"""

Эти ошибки автоматически преобразуются в соответствующие HTTP-статусы
через exception handlers.

Real-time функциональность
===========================

WebSocket
---------

Используется для real-time чата:

* Подключение через WebSocket по URL ``/api/v1/chat/ws``
* Аутентификация через JWT-токен в query параметрах
* Отправка и получение сообщений в реальном времени

Redis Pub/Sub
-------------

Для синхронизации между несколькими инстансами приложения:

* Сообщения публикуются в Redis канал
* Все инстансы подписаны на этот канал
* Сообщения доставляются всем подключенным клиентам
