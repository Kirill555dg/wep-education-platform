============
Введение
============

Обзор проекта
=============

Web Education Platform Backend - это серверная часть системы управления онлайн-обучением (LMS).
Проект реализует REST API для управления учебным процессом, включая работу с пользователями,
классами, уроками, домашними заданиями и теоретическими материалами.

Цели и задачи
=============

Основные цели проекта:

1. **Управление пользователями**: регистрация, аутентификация, управление ролями (преподаватель/студент)
2. **Управление учебным процессом**: создание и редактирование классов, уроков, домашних заданий
3. **Проверка знаний**: система задач с автоматической и ручной проверкой
4. **Статистика и аналитика**: отслеживание прогресса студентов
5. **Real-time коммуникация**: чат для взаимодействия преподавателей и студентов

Требования к системе
=====================

Для разработки и запуска проекта требуется:

* Python 3.13+
* PostgreSQL 14+
* Redis 7+ (опционально, для real-time функций)
* Docker и Docker Compose (для контейнеризации)

Установка и запуск
==================

Локальная разработка
--------------------

1. Клонируйте репозиторий
2. Создайте виртуальное окружение: ``python -m venv .venv``
3. Активируйте окружение: ``source .venv/bin/activate`` (Linux/macOS) или ``.venv\\Scripts\\activate`` (Windows)
4. Установите зависимости: ``pip install -r requirements.txt``
5. Скопируйте ``.env.example`` в ``.env`` и настройте переменные окружения
6. Примените миграции: ``alembic upgrade head``
7. Запустите сервер: ``python -m app.scripts.run_server``

Запуск через Docker
-------------------

.. code-block:: bash

   docker-compose up backend

Структура проекта
=================

::

    backend/
    ├── alembic/              # Миграции базы данных
    ├── app/
    │   ├── api/              # API эндпоинты (контроллеры)
    │   │   ├── v1/           # API версии 1
    │   │   └── middleware/   # Middleware для обработки запросов
    │   ├── core/             # Основные компоненты (конфигурация, безопасность)
    │   ├── db/               # Настройка базы данных
    │   ├── domain/           # Доменные ошибки и бизнес-логика
    │   ├── models/           # ORM модели (SQLAlchemy)
    │   ├── repositories/     # Репозитории для работы с данными
    │   ├── schemas/          # Pydantic схемы (DTO)
    │   ├── services/         # Бизнес-логика (Service Layer)
    │   ├── realtime/         # WebSocket и real-time функциональность
    │   └── scripts/          # Вспомогательные скрипты
    ├── tests/                # Тесты
    ├── docs/                 # Документация (Sphinx)
    └── requirements.txt      # Зависимости проекта

Архитектурные слои
==================

API Layer (Контроллеры)
-----------------------

Эндпоинты FastAPI, которые обрабатывают HTTP-запросы и вызывают сервисы.
Расположены в ``app/api/v1/``.

Service Layer (Сервисы)
-----------------------

Бизнес-логика приложения. Сервисы координируют работу репозиториев и реализуют
бизнес-правила. Расположены в ``app/services/``.

Repository Layer (Репозитории)
------------------------------

Абстракция доступа к данным. Репозитории выполняют операции с базой данных через
SQLAlchemy ORM. Расположены в ``app/repositories/``.

Data Layer (Модели)
-------------------

ORM модели SQLAlchemy, представляющие структуру базы данных. Расположены в ``app/models/``.

Schema Layer (DTO)
------------------

Pydantic схемы для валидации входящих данных и сериализации ответов API.
Расположены в ``app/schemas/``.
