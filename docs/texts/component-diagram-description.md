Диаграмма основных компонентов системы (см. на рисунке 3.1) предназначена для фиксации состава программных компонентов WEP LMS и их интерфейсов взаимодействия на уровне клиент–серверной модели, включая каналы связи и тип обмена данными между компонентами.

- **GUI (Web Client, React/TS SPA)** — клиентское веб‑приложение, реализующее пользовательские сценарии ролей «преподаватель» и «студент». Входной интерфейс — действия пользователя; выходные интерфейсы — HTTP/REST запросы (JSON DTO) к серверному API и WebSocket‑соединение для чата.

- **API Controller (FastAPI, /api/v1)** — серверный компонент, принимающий внешние запросы клиентской части и маршрутизирующий их к прикладным модулям предметной области. Входные интерфейсы — HTTP/REST и WebSocket; выходные интерфейсы — вызовы прикладных модулей по их интерфейсам и доступ к хранилищам через SQL и Pub/Sub (в части realtime).

- **Auth Module** — прикладной модуль аутентификации и управления сессией пользователя (выдача/проверка токенов, роль). Входной интерфейс — вызовы со стороны API Controller по интерфейсу `IAuth`; выходной интерфейс — операции чтения/записи в базе данных через `IDatabase`.

- **Classroom Module (classes + membership + invites)** — прикладной модуль управления классами и членством (создание класса, вступление, состав учеников, инвайт‑коды). Входной интерфейс — `IClassroom`; выходной интерфейс — `IDatabase`.

- **Lesson Module** — прикладной модуль управления уроками (создание/публикация/получение уроков). Входной интерфейс — `ILesson`; выходной интерфейс — `IDatabase`.

- **Homework Module** — прикладной модуль управления домашними заданиями (создание, публикация, получение ДЗ и состава задач). Входной интерфейс — `IHomework`; выходной интерфейс — `IDatabase`.

- **Problem Module (problem library)** — прикладной модуль управления базой задач (CRUD задач, предоставление задач для сборки ДЗ). Входной интерфейс — `IProblem`; выходной интерфейс — `IDatabase`.

- **Testing Module (answer submit/check)** — прикладной модуль приёма ответов и автоматической проверки (обновление статуса/попыток/баллов). Входной интерфейс — `ITesting`; выходной интерфейс — `IDatabase`.

- **Result/Statistics Module** — прикладной модуль выдачи статистики и прогресса (по студенту/классу/ДЗ). Входной интерфейс — `IStatistics`; выходной интерфейс — `IDatabase`.

- **Theory Module** — прикладной модуль предоставления теоретических материалов, связанных с уроками. Входной интерфейс — `ITheory`; выходной интерфейс — `IDatabase`.

- **Chat Module (HTTP messages)** — прикладной модуль хранения и выдачи истории сообщений чата. Входной интерфейс — `IChat`; выходной интерфейс — `IDatabase`.

- **Realtime Chat Subsystem (WS + presence/typing)** — подсистема realtime‑чата, обеспечивающая WebSocket‑обмен событиями и хранение краткоживущих состояний (presence/typing). Входной интерфейс — `IRealtimeChat`; выходной интерфейс — `IPubSub` (Redis) для распространения событий и поддержки presence/typing.

- **Database System (PostgreSQL)** — компонент персистентного хранения данных и источник истины доменных сущностей. Входной интерфейс — SQL‑операции через `IDatabase`; прямого интерфейса для клиентского компонента не предусмотрено.

- **Redis (Pub/Sub + ephemeral presence)** — инфраструктурный компонент, используемый для Pub/Sub обмена событиями realtime‑чата и хранения краткоживущих состояний presence/typing. Входной/выходной интерфейс — `IPubSub`, используемый серверной частью.

- **pgAdmin (DB Administration UI)** *(опционально, присутствует в конфигурации системы)* — инструмент администрирования базы данных. Входной интерфейс — действия администратора; выходной интерфейс — SQL‑подключение к PostgreSQL.
