Диаграмма основных компонентов системы (см. на рисунке 3.1) предназначена для фиксации состава программных компонентов WEP LMS и их интерфейсов взаимодействия на уровне клиент–серверной модели, включая каналы связи и тип передаваемых данных.

- **Web Client (React/TypeScript SPA)** — клиентское веб‑приложение, реализующее пользовательские сценарии ролей «преподаватель» и «студент» и формирующее запросы к серверной части. Входной интерфейс компонента — действия пользователя через веб‑интерфейс; выходные интерфейсы — HTTP(S) запросы (REST/JSON) и WebSocket‑соединение для чата, направляемые через фронтенд‑веб‑сервер.

- **Frontend Web Server (Nginx)** — компонент доставки статических ресурсов клиентского приложения и проксирования обращений к серверному API по единой точке входа. Входные интерфейсы — HTTP(S) запросы браузера (загрузка SPA) и обращения по `/api` (REST и WebSocket Upgrade); выходные интерфейсы — проксированные HTTP/REST запросы и WebSocket‑трафик к Backend API.

- **Backend API (FastAPI)** — серверное приложение, реализующее доменную логику LMS и предоставляющее публичный программный интерфейс для клиентской части. Входные интерфейсы — HTTP/REST запросы (JSON DTO) и WebSocket‑соединения (чат); выходные интерфейсы — SQL‑доступ к PostgreSQL для чтения/записи доменных данных и взаимодействие с Redis по Pub/Sub для распространения realtime‑событий чата.

- **PostgreSQL (Relational DB)** — компонент персистентного хранения данных системы и источник истины для доменных сущностей и фактов (учётные записи, классы, уроки, задания, задачи, статистика, сообщения). Входной интерфейс — SQL‑операции чтения/записи, выполняемые Backend API и инструментальными компонентами; прямого интерфейса для клиентской части не предусмотрено.

- **Redis (Pub/Sub)** *(опционально, присутствует в конфигурации системы)* — инфраструктурный компонент обмена сообщениями по схеме publish/subscribe, используемый Backend API для fanout realtime‑событий чата между экземплярами серверного приложения. Входные/выходные интерфейсы — Pub/Sub каналы, используемые Backend API.

- **DB Migrations (Alembic)** — инструментальный компонент управления схемой базы данных, выполняющий применение миграций к PostgreSQL в составе серверной части. Входной интерфейс — управляющий запуск в окружении backend; выходной интерфейс — SQL‑операции изменения схемы в PostgreSQL.

- **pgAdmin (DB Administration UI)** *(опционально, присутствует в конфигурации системы)* — инструмент администрирования базы данных, предназначенный для обслуживания и диагностики PostgreSQL. Входной интерфейс — действия администратора через UI; выходной интерфейс — SQL‑подключение к PostgreSQL.
