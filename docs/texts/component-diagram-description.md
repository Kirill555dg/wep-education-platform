Диаграмма основных компонентов системы (см. на рисунке 3.1) предназначена для фиксации состава основных компонентов WEP LMS и их взаимодействия в рамках клиент–серверной модели, включая каналы связи и тип передаваемых данных.

- **GUI (Web Client, React/TS SPA)** — клиентское веб‑приложение, предоставляющее пользовательский интерфейс для сценариев ролей «преподаватель» и «студент». Получает от пользователя команды и вводимые данные; передаёт на сервер запросы по HTTP/REST (JSON) и получает ответы, а для чата устанавливает WebSocket‑соединение и обменивается событиями.

- **API Controller (FastAPI, /api/v1)** — серверный компонент, принимающий запросы от GUI и предоставляющий единый программный интерфейс системы. Получает HTTP/REST запросы и WebSocket‑сообщения; возвращает клиенту JSON‑ответы и realtime‑события, используя доменные модули и хранилища данных.

- **Auth Module** — модуль аутентификации и управления сессией (регистрация/вход, выпуск и проверка JWT, активная роль пользователя). Получает учётные данные и запросы на проверку токена; возвращает токен и данные пользователя, используя записи пользователей и профилей в базе данных.

- **Access Control Module** — модуль контроля доступа, обеспечивающий проверку прав на доменные операции (роль пользователя, членство в классе, владение классом преподавателем). Получает контекст пользователя и идентификаторы сущностей; возвращает решение о допуске и тем самым ограничивает операции остальных модулей на основании данных из базы.

- **Classroom Module (classes + membership + invites)** — модуль управления классами и членством (создание класса, вступление по invite‑коду, список учеников). Получает команды на создание/обновление/вступление и параметры пагинации; возвращает сведения о классах и составе участников, читая и изменяя записи классов и связей членства в базе данных.

- **Lesson Module** — модуль управления уроками в рамках класса (создание, публикация, получение списка и деталей). Получает идентификатор класса и параметры выборки; возвращает данные уроков и их состояния публикации на основе записей уроков в базе данных.

- **Homework Module** — модуль управления домашними заданиями (создание, публикация, получение ДЗ, выдача состава задач ДЗ). Получает идентификатор урока/ДЗ и команды учителя; возвращает метаданные ДЗ и список задач, используя связи “урок–ДЗ” и “ДЗ–задачи” в базе данных.

- **Problem Module (problem library)** — модуль базы задач (создание/редактирование/получение задач для сборки ДЗ). Получает команды CRUD и параметры выборки; возвращает описания задач (для учителя — полные данные, для ученика — без ответов), используя записи задач в базе данных.

- **Testing Module (answer submit/check)** — модуль приёма ответов и автоматической проверки. Получает ответы ученика по задачам ДЗ и затраченное время; возвращает обновлённое состояние попытки (баллы/статус/количество попыток), изменяя записи статистики выполнения в базе данных.

- **Result/Statistics Module** — модуль выдачи статистики и прогресса (по студенту, по классу, по конкретному ДЗ). Получает запросы на выборку статистики и агрегатов; возвращает показатели выполнения и прогресса, используя записи статистики и связей участников классов в базе данных.

- **Theory Module** — модуль предоставления теоретических материалов, привязанных к урокам. Получает запросы на выборку материалов; возвращает структуру и содержимое материалов на основе записей теории и связей “урок–материал” в базе данных.

- **Chat Module (HTTP messages)** — модуль хранения и выдачи истории сообщений чата класса по HTTP. Получает запросы на чтение/создание сообщений; возвращает список сообщений и подтверждение сохранения, используя записи чатов и сообщений в базе данных.

- **Realtime Chat Subsystem (WS + presence/typing)** — подсистема realtime‑чата, обеспечивающая WebSocket‑обмен событиями, доставку сообщений и краткоживущие состояния присутствия/набора текста. Получает сообщения и события от клиента по WebSocket; передаёт участникам чата события и использует Redis для Pub/Sub распространения и хранения краткоживущих маркеров presence/typing.

- **Database System (PostgreSQL)** — компонент персистентного хранения и источник истины доменных данных LMS. Получает от серверных модулей операции чтения/записи; предоставляет им сохранённые доменные сущности и факты выполнения.

- **Redis (Pub/Sub + ephemeral presence)** — инфраструктурный компонент, используемый подсистемой realtime‑чата для распространения событий и хранения краткоживущих состояний presence/typing. Получает публикации событий и операции над краткоживущими ключами; предоставляет подписчикам события и данные presence/typing.
